# Fluff

SMVD 사용자경험디자인 II — 5주차 워킹 프로토타입

> 갤러리 속 최애 사진으로 세상에 하나뿐인 솜인형을 만들고, 말랑이처럼 만지고, 3D 방에 진열하고, 친한 친구만 초대해 함께 구경하는 iOS 앱

## 문제와 사용자

- **문제**: 좋아하는 대상의 사진은 갤러리에 쌓여 있지만 보는 것 말고는 즐길 방법이 없다. 실물 굿즈는 비싸고, 진열하기엔 공간과 남의 시선이 부담스럽다. 결과물은 친한 덕메 몇 명에게만 보여주고 싶은데 SNS는 공개 범위를 고르기 어렵다.
- **사용자**: 22세 대학생 아이돌 덕후. 용돈이 한정적이고, 가족과 살며, 지하철이나 잠들기 전처럼 짧은 틈에 폰을 쓴다.
- **KPI**: 유저당 하루 인형 터치 20회·방 체류 3분 / 친구 기능 사용률 40% / 방 공유 링크 가입 전환 15%

## 구현한 기능

| 와이어프레임 | 구현 내용 |
|---|---|
| 0. 간편 가입 | Apple·카카오 시작 버튼 (실제 로그인은 미연결) |
| 1. 홈 | 3D 내 방, 빈 상태 안내, 인형 길게 눌러 옮기기, 취소/완료, "침대에 배치했어요 · 되돌리기" |
| 2·3. 인형 만들기 | 사진 선택(앨범 권한 없이) → 자동 누끼 + 지우기·복원 브러시 → 인형 모양·속재료·이름 → 꿰매는 중(나가기 확인) → 완성 → 방에 배치 |
| 3-1~3-4. 인형 액션 | 만지기(속재료별 눌림·햅틱·소리), 춤추기(적용하면 방에서도 계속 춤춤), AR 예절샷(저장 전엔 기기에 안 남음), 공유 |
| 4. 방 꾸미기 | 가구·벽지·바닥재·러그·장식, 가구 끌어 옮기기(격자, 겹침 방지), 두 번 탭해 컬러·사진으로 꾸미기(크기·반전·회전) |
| 5. 친구 | 친구 목록, 아이디로 추가, 친구 방 구경·좋아요, 방명록, 알림함 |
| 멀티 룸 | SharePlay로 같은 방에 들어가 인형 이동·만지기·춤을 실시간으로 공유 |

## 실행 방법

1. Xcode 26 이상에서 `Malrang.xcodeproj`를 연다.
2. Signing & Capabilities에서 Team을 자기 계정으로 바꾼다.
3. iPhone(iOS 26.4 이상)을 연결하고 ▶︎ Run.

- 시뮬레이터에서도 대부분 동작하지만 **자동 누끼, AR, SharePlay는 실제 iPhone에서만** 된다.
- SharePlay는 서로 다른 Apple ID의 기기 두 대를 FaceTime으로 연결한 뒤, 홈 상단 SharePlay 아이콘 → "SharePlay 시작".

## 기술 스택

- SwiftUI, SwiftData, `@Observable` (외부 라이브러리 없음)
- 3D: RealityKit (`ARView`를 감싸 길게 눌러 끌기·두 번 탭·촬영 처리)
- 누끼: Vision `VNGenerateForegroundInstanceMaskRequest`
- AR: ARKit 평면 인식 + 코칭 오버레이
- 멀티 룸: GroupActivities (SharePlay)
- 친구 서버: 미정 → `FriendAPI` 프로토콜 뒤 `MockFriendAPI`

```
Malrang/
├── App/            # 진입점, 탭, 앱 상태
├── DesignSystem/   # 색·간격·모서리 토큰, 버튼, 칩
├── Models/         # Doll, RoomItem, FurnitureKind, RoomLayout(배치 규칙)
├── Features/       # Onboarding, Create, Doll, Squishy, Room, Friends
└── Services/       # 누끼, 친구 API, SharePlay 멀티 룸
```

## 효과가 있었던 핵심 프롬프트

1. **규칙 파일(CLAUDE.md)을 먼저 만들기**
   > "수정된 PRD입니다. 이를 바탕으로 swiftui 앱의 규칙파일을 작성해주세요" + "디자인 관련 규칙도 추가해주세요"

   색·간격·모서리 토큰, 금지 목록(그라데이션, 보라색 AI 스타일, 이모지 UI), 화면별 필수 상태(빈 화면·실패·권한 거부)를 파일로 고정했다. 이후 프롬프트가 짧아졌고 AI가 보라색 그라데이션이나 요청 안 한 화면을 만들지 않았다.

2. **와이어프레임 링크 + 범위 한정**
   > "lofi 와이어프레임입니다. 방이나 가구 같은 3D 에셋이 필요한 부분은 나중에 따로 작업해서 넣을 예정이라 임시로 작업해주세요"

   "임시로"를 명시하자 임시 도형을 쓰되, 나중에 같은 이름의 USDZ를 넣으면 자동으로 바뀌는 구조로 만들었다.

3. **증상을 구체적으로 말하기**
   > "ar화면에 들어갔는데 카메라가 안뜨는데 원래 그런건가요?"

   AI가 원인 후보를 나눠 묻고(권한 문구 / 미지원 기기 / 빈 화면), 실기기 로그를 붙여 원인을 좁혔다.

4. **기능을 한 단계씩 추가하기**
   > "shareplay로 실시간공유를 테스트해보고 싶어요" → "동작을 공유하는 것도 추가해주세요"

   한 번에 다 시키지 않고 위치 공유 → 동작 공유로 나눠 요청했다.

## 실패한 시도와 해결

| 문제 | 원인 | 해결 |
|---|---|---|
| AR 화면이 하얗게 비어 있음 | 홈의 3D 방과 AR 카메라, 3D 화면 두 개가 동시에 그려짐 | AR·멀티 룸을 여는 동안 홈의 3D 방을 내림 |
| 카메라 권한 창이 안 뜸 | Info의 권한 설명 문구가 빈 문자열 | 문구를 채우고 앱 재설치 |
| 3D 방의 인형이 반투명하게 보임 | RealityKit은 불투명도 텍스처의 **빨강 채널**을 읽음 (알파가 아님) | 이미지 알파로 흑백 마스크를 따로 만들어 적용 |
| 시뮬레이터에서 누끼 실패 | Vision 누끼가 시뮬레이터에서 동작하지 않음 | "피사체를 찾지 못했어요" 실패 화면 + "사진 그대로 쓰기" 대안 추가 |
| 곰인형 프리셋이 카드 밖으로 넘침 | 도형 비율 계산 오류 | 전체 높이(약 1.35배) 기준으로 다시 계산 |
| 방이 화면 양옆에서 잘림 | 화면 크기가 정해지기 전에 카메라 거리를 계산 | 화면 크기가 바뀔 때마다 카메라를 다시 맞춤 |
| 벽지 색이 늦게 바뀜 | 다시 그릴 때마다 없는 USDZ 파일을 찾음 | 찾은 결과를 기억해 한 번만 찾음 |

## 검증 체크리스트

| 항목 | 결과 |
|---|---|
| 빈 상태 / 로딩 / 에러 화면 | ✅ 빈 방, 친구 0명, 누끼 실패, 불러오기 실패, 카메라 거부, AR 미지원 |
| 새로고침(앱 재시작) 후 데이터 유지 | ✅ SwiftData 저장 |
| 버튼 두 번 누르기 | ⚠️ 인형 완성은 한 번만 저장되지만 전 화면을 점검하지는 못함 |
| 작은 화면(375pt) | ⚠️ 미확인 |
| 명도 대비 4.5:1 | ✅ 텍스트·배경 색 조합을 계산해 기준 미달 색을 조정 |
| 색만으로 정보 구분 안 함 | ✅ 선택 상태에 체크 아이콘·테두리 함께 표시 |
| VoiceOver 라벨 | ⚠️ 주요 버튼만 지정 |
| API 키 하드코딩 | ✅ 없음 |
| 실제 인물 사진을 저장소에 커밋 | ✅ 없음 (테스트 이미지는 SF Symbols 동물) |
| AI 없이 색 하나 바꾸기 | ✅ `Assets.xcassets`의 색 하나만 바꾸면 앱 전체가 바뀜 |

## 남은 한계와 다음 단계

- **임시 3D**: 방·가구는 기본 도형, 인형은 합성 이미지를 세운 판이다. 3D 에셋과 솜인형 메시(누끼 부풀리기)를 만들어 교체해야 한다.
- **임시 동작**: 춤은 단순한 움직임으로 흉내 냈고, 효과음은 시스템 소리다.
- **로그인·친구 서버 없음**: 친구 데이터는 목업이다. 멀티 룸만 실제로 기기 간 통신한다.
- **SharePlay 한계**: 참여자 이름을 알 수 없어 누가 만졌는지 표시하지 못한다. 가구 꾸미기는 공유되지 않는다.
- **없는 기능**: 인형 삭제, KPI 측정, 다크 모드.
- **배포**: iOS 앱이라 웹 배포 주소 대신 TestFlight 또는 시연 영상으로 제출 예정. <!-- TODO: 링크 추가 -->
